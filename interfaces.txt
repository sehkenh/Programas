As a general rule, methods in interfaces are declared without any body. In practice, this
means that you can define interfaces that do not make assumptions about how they are implemented.
Once it is defined, any number of classes can implement an interface. Also one class can implement
any number of interfaces.

En resumen. Se hacen los métodos dentro de las interfaces sin body(es una suerte de clase), una vez
creada cualquier cantidad de clases pueden usar la interfaz, así como una clase puede implementar
ilimitadas interfaces.

Para implementar la interfaz, se deben usar todos los métodos de la interfaz en la clase.

one interface, multiple methods. - Polymorphism

They disconnect the definition of a method or set of methods from the inheritance hierarchy. Since Interfaces
are in a different hierarchy from classes, it is possible for classes that are unrelated in terms of the class
hierarchy to implement the same interface. This is where the real power of interfaces is realized.

Recordar diferencia entre definir una interface e implementar una interface.

##Defining an Interface##

access interface name {
    return-type method-name1(parameter-list);

    type final-varname1 = value;
    ...

    }

Si no se define el acceso, entonces se define default, y sólo está disponible para otros miembros
del package el cual fue declarado. Cuando es declarado public, interface can be used outside its package.
En este caso debe ser la única interfaz declarada como public en el archivo y el archivo debe tener el mismo
nombre de la interface. name es el nombre de la interface. Note que los methods no tienen body. They
are essentially, abstract methods.

Las clases que invocan a la interface deben hacer uso de todos los methods contenidos en la interface.

En JDK 8 en adelante, se cambió la forma de implementar las interfaces, que hasta ahora eran del tipo
sin body. En JDK8 es posible añadir un default implementation to an interface method. Se añadió
un static interface methods, y en JDK 9 se puede hacer uso de private methods en las interfaces.
Ahora es posible que tengan cierto comportamiento.

Variables pueden ser declaradas dentro de las interfaces, son static o final, lo que implica
que no pueden ser cambiadas por la clase que los implementa. Deben ser inicializadas.

##Implementing Interfaces##

Una vez definida una interface, puede ser implementada por una o más clases. Para implementar una
interface, se debe incluir la cláusula implements, y después los métodos requeridos por la interface.

class class-name [extends superclass] [implements interface]
    //class body

Si una clase implementa más de una interface, estas se separan por coma.
Los methods deben ser public al ser implementados por la interface.

class Client implements Callback {
    //Implements Callback's interface
    public void callback(int p) {
        System.out.println("callback called with " + p);
    }
}

Es común que al implementar las clases también se hagan methods propios de la clase en los programas.

class Client implements Callback {
    //Implements Callback's interface
    public void callback(int p) {
        System.out.println("callback called with " + p);
    }

    void ninIfaceMeth() {
        System.out.println("Classes that implement interfaces " + "may also define other members, too.");
    }
}

##Accessing Implementations through interface references##

class TestIface {
    public static void main(String[] args){
        Callback c = new Client();
        c.callback(42)
    }
}

Notice that variable c is declared to be of the interface type Callback, yet it was assigned an instance of Client.
Although c can be used to access the callback() method, it cannot access any other members of the Client class. Thus,
c could not be used to access nonIfaceMeth() since it is defined by Client but not Callback.

//Another implementation of Callback.
class AnotherClient implements Callback {
    //Implement Callback's interface
    public void callback(int p) {
        System.out.println("Another version of callback"):}
        System.out.println("p squared is " + (p*p));
    }
}

Now, trying the following class:

class TestIface2 {
    public static void main (String[] args) {
        Callback c = new Client();
        AnotherClient ob = new AnotherClient();

        c.callback(42);

        c = ob; //c refers to AnotherClient object
        c.callback(42); //Es como si dijera ob.callback(42)
    }
}

The output:

Another version of callback
p squared is 1764

##Partial Implementations##
The class that do the incomplete implementation of the interface must be declared as abstract.

Then:

abstract class Incomplete implements Callback {
    int a,b;

    void show() {
        System.out.println(a + " " + b);
    }
}

##Nested Interface##

class A {
    public interface NestedIF {
        boolean isNotNegative(int x);
    }
}

// B implements the nested interface.

class B implements A.NestedIF {
    public boolean isNotNegative(int x) {
        return x < 0 ? false: true;
    }
}

class NestedIFDemo {
    public static void main(String[] args) {

        // use a nested interface reference
        A.NestedIF nif = new B();

        if(nif.isNotNegative(10))
            System.out.println("10 is not negative");
        if(nif.isNotNegative(-12))
            System.out.println("This won't be displayed");
    }
}
